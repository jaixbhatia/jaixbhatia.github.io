Project 1: Colorizing the Prokudin-Gorskii Photo Collection

Overview

This project focuses on automatically producing color images from the digitized Prokudin-Gorskii glass plate images. Sergei Mikhailovich Prokudin-Gorskii (1863-1944) was a pioneer in color photography who captured thousands of color pictures of the Russian Empire by recording three exposures of every scene using red, green, and blue filters. The goal is to extract the three color channel images, align them properly, and combine them into a single RGB color image.

Approach

Single-Scale Alignment: I implemented an exhaustive search algorithm that searches over a window of possible displacements (+-15 pixels) and scores each displacement using image matching metrics. I used two different metrics: L2 distance (Euclidean Distance) and Normalized Cross-Correlation (NCC).

Image Pyramid: For large images (tiff files), I implemented an image pyramid approach that processes images at multiple scales, starting from the coarsest scale and refining the alignment as we move down the pyramid. This significantly speeds up the alignment process for high-resolution images since we running single-scale alignment multiple times on coarser images is much faster than running a large window on the original image

Specifically, I use cv2.resize to scale the image down by a scale factor, then I find the best shift parameter. I pass this up the recursion stack and use it to scale the image back up to the original size (via coarse shift * scale factor)

Simple example: Imagine you have a huge 4000x4000 image and you try every possible shift in a 31x31 window. That is about 15 billion comparisons. With an image pyramid, you first align on a tiny 500x500 version (only ~0.2 billion comparisons), then refine on 1000x1000, 2000x2000, and finally 4000x4000 with much smaller windows. Altogether thats only about 1.3 billion comparisons. Result: >10x speedup.

Border Cropping: I crop 10% of the border from each channel to avoid alignment issues caused by border artifacts that don't contain useful image information.

Generally, I use cv2 to read the images and split the images into the BGR channels. Then I crop the borders. Finally I align R and B to G, but I also experimented with using R as the anchor to compare performance. I then apply the best shift parameters found via single-scale alignment or the image pyramid approachto R and B via np.roll and stack them together with G to get the final aligned image.

Challenges and Solutions

Challenge 1: Different brightness values between color channels (since red, green, and blue plates were captured separately)
Solution: Used Normalized Cross-Correlation instead of raw pixel comparison. Using L2 distance meant a high bias due to this contrast difference (e.g. a bright red channel vs a dim red channel would still have a high L2 distance even if perfectly aligned). By scaling each pixel by its mean value, we can normalize the brightness of the channels, which makes the comparison invariant to contrast differences.

Challenge 2: Pyramid approach runtime optimization
Solution: I set a coarse_shift (-10, 10) and a normal_shift (-5, 5). This improved runtime to <5 seconds for all images, since a greater shift range on the large tiff images would have taken too long. The hypothesis was that if my coarsest image had a large shift range, it would find an accurate shift that would not mess up the downstream alignment (and that going down the pyramid means we are safe searching through a smaller shift range)

Challenge 3: Image not lined up using pyramid approach
Solution 1: I noticed that the coarsest scale of the pyramid was a 64x64 image, and that I was getting a shift of ~5 for some images. During the scaling up process (going back down the pyramid), this greatly affected the shifts (e.g. if I got a shift of 5 on the coarsest scale, it would be 5*4 = 20 on the next scale, 5*4*4 = 80 on the next scale, etc.). So I changed the base case to be 256x256, which greatly improved the shifts. Turns out that the 64x64 messed up too much of the image for the output scale to be useful, which affected the downstream alignment. I plotted the images at each step of the pyramid to confirm my hypothesis.
Solution 2: Changed the reference image to green instead of red. The green channel is more aligned to both red and blue so the shifts needed to align red->green and blue->green are smaller. This means less cropping, less accumulated error, and better alignment
